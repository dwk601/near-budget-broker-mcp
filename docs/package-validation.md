# Package validation and verified compatibility

## Run

```sh
npm ci
npm run test:package && npm run typecheck
```

The package suite **cleans and builds dist itself** before packing; no prepack hook is needed or assumed. For operator tarball creation, remove `dist`, run `npm run build`, then `npm pack`. Node 24+ and Docker Compose >=2.24.4 are required (render tests do not start containers or require a Docker daemon). npm dependencies may need registry access; no live faucet, payment or public NEAR RPC is used by packaging tests.

## What the package suite checks

`test/package/package.test.ts` creates one OS temp directory and a fresh consumer project **outside the checkout**, then:

1. Removes dist to prevent stale artifacts shipping, runs build, `npm pack --json --pack-destination TEMP`, and installs that tarball in the fresh project with scripts disabled. Supports npm's array (≤11) and package-keyed (12) pack manifests. The installed bin resolves inside that consumer, not the worktree.
2. Inspects the actual archive and compares manifest entries. Requires dist/bin/README/LICENSE/skill/examples/Docker files; uses exact filename allowlists for examples, Docker and skills (generated dist is allowed separately). Rejects tests, node_modules, .env, state/databases and private-key/token material, including bare `ed25519:` base58 secrets and private_key/secret_key JSON. Guard regression cases reject unreviewed native-key, owner.json, receivers.json and fixtures.env artifacts. No postinstall launch hook.
3. Parses every shipped example JSON, validates MCP npx argv and version, checks policy/grant shape with exact NEAR conversion, and validates the skill's simple YAML name/description frontmatter. Replaces only the daemon-config public-key placeholder with an ephemeral real public key and loads it through the production config loader (including yocto conversion).
4. Launches the **installed bin** for missing/nonexistent token errors: nonzero, clean stderr only, no stdout/stacks/token leakage. Exercises real local encrypted owner/custody initialization, config flag/env fallback, valid offline signed receipt/checkpoint verification and corrupt JSON/schema/signature failures. Missing receipt files are checked for exit 1 / AUDIT_UNAVAILABLE in both text and JSON modes; invalid audit keys with parseable inputs are checked for exit 1 / valid:false on stdout with empty stderr.
5. Executes 32 owner admin forms/optional positional variants/flags against a local recording stub using encrypted owner unlock and real signed HTTP requests. The stub validates strict admin schemas; it is not a live broker/owner-auth security test. Inputs use UUIDs, not generic labels. Tests check monetary conversion, force behavior, sequence exports, protected token files and **both plain and JSON path + credentialId output**. Refusal cases validate documented exits 0/1/2/3, including stale policy-write revision exit 2 and authorization exit 3.
6. Verifies help variants without credentials/network. `docs/cli-help.txt` is captured from current real CLI help and compared byte-for-byte with the installed help; root/owner help uses stdout, **mcp --help / help mcp use stderr with empty stdout**, all exit 0.
7. Times 30 separate installed `--help` processes, prints nearest-rank p95 and requires **≤1000 ms**, meaningful help, exit 0 and no stderr. Fast usage errors do not count. Direct stdout reporting keeps the timing visible even when Vitest hides passing console logs.
8. Cleans consumer/tarball/ephemeral secrets in suite cleanup, including assertion/setup failure. Only normal git-ignored dist build output remains. It does not write fixture/state/tarball artifacts into the checkout.

The package suite also renders the shipped base Compose file, base+prebuilt, base+resources and all three with real `docker compose config --quiet` / JSON assertions using `assertComposeConfig`. It checks file-secret paths, BB_IMAGE/BB_DATA_VOLUME, loopback ports, sole named-volume mount, preserved hardening, prebuilt build removal and resource bounds. The installed build context is checked against the package root using canonical paths (including cwd aliases); only validated context/override differences are normalized on a clone before the shared helper's exact base-deployment assertions. No images, containers, volumes or networks are created by rendering.

`test/package/lifecycle.test.ts` executes production broker defaults with fake chain/clock dependencies: pending approval remains pending at 299999 ms, expires at 300000 ms and releases both holds. Queued and persisted approved work likewise expire on dispatch processing at 300000 ms while globally frozen, release both holds and cannot be revived by unfreeze or same-key replay. Expired/rejected/cancelled requests retain their keys; RATE_LIMITED/MAX_OUTSTANDING stored denials remain denied after backoff/capacity recovery, while a new authorized request can be admitted. Queued work encountering an unbound standing grant returns to pending owner approval without signing/broadcasting or consuming that grant; explicit owner approval then permits the same request to execute.

`npm run test:cli` additionally executes current CLI/main behavior against fake chain/RPC dependencies: local validation/stale policy revisions, verification corruption, authentication/Host/Origin exits, every daemon diagnostic, per-key locks across data directories and crash recovery. `npm run test:isolation` exercises real Docker build/create/provision/up with file secrets/read-only rootfs and SIGKILL/restart using isolated fake RPC.

## Compatibility assumptions

- Package is private and npx uses a **local tarball**, not a claim of registry publication. Explicit clean-build-before-pack is required and performed by the suite; there is no prepack hook.
- Tarball allowlist intentionally includes README/examples/skill/Docker/dist, not full docs, src, fixture scripts, lockfile or compiler config. README's full-guide links target the source checkout. Build the daemon image and run live fixtures from source, or supply a separately trusted **BB_IMAGE** via the prebuilt override.
- Only fixture `broker-key.json` is encrypted; reuse it with exact binary `master.secret`. `recovery.json` (full-access key) and `receivers.json` contain plaintext ed25519 private keys at 0600; the whole fixtures directory, including the master, is secret. Base Compose file secrets already support that binary file through **BB_MASTER_FILE**. No environment/content-secret override remains.
- Absolute **BB_MASTER_FILE/BB_CONFIG_FILE** paths are protected operator exceptions (outside repo, 0600 files/0700 directories). Master must be a regular non-symlink file, 0600 or 0400, owned by the daemon uid (mapped uid 1000), not merely readable by it; config must be readable by that uid. Invalid master-file protection reports BAD_MASTER_SECRET. Daemon receives **BB_MASTER_SECRET_FILE**; direct BB_MASTER_SECRET is refused. Keep image/volume variables consistent, Compose **create before provisioning**, and mount stdin-only encrypted provisioning at **/var/lib/budget-broker** as uid 1000.
- `broker.sqlite` and WAL/SHM sidecars are 0600, including under a loose umask; database/sidecar symlinks are refused. SQLite data/per-custody-key lock files are retained; kernel lock release handles crashes. No stale PID/tmp-lock deletion procedure applies to current locks. Independent users/hosts/volumes are not distributed fencing. One daemon/trust root per custody key remains mandatory.
